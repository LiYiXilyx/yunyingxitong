# T05 工程与真实验收记录

日期：2026-10-26。T05 数据入库、标准化、指标和健康接收工程已实现，整体验收状态仍为 **partial**。当前可运行内部库和手动 synthetic 演练；真实端到端适配及定时 worker 尚未装配，真实数据投递未启用，不执行经营派单。

## 已实现范围

- 原始页暂存、批次完整性检查、源事实版本和幂等提交；成功状态、水位及 PendingEvaluation 原子持久化，部分批次不进入完整指标。
- 显式映射驱动的订单、退款、库存和合成/手工商品 BOM 标准化；拆合去重、状态更正、退款申请来源区分、共仓范围和 Decimal/时区边界检查。
- 指标按明确业务窗口及覆盖证据生成；缺完整覆盖时返回 insufficient，不以缺失补零。
- 持久健康扫描、单调 revision 和待投递命令，以及 NocoBase 健康接收、权限/绑定版本核验、幂等收执、问题合并与恢复显示。
- 纯对账分类工具，显示稳定身份摘要和字段；不同查询窗口拒绝直接比较，缺值和非法值标记数据不足，差异不会自动被解释。

PendingEvaluation 是后续评估的持久入口；当前没有实现 T06 业务规则执行或 T07 经营任务派发。健康数据待办不代表经营任务。

## 本地复现入口

先准备既有本地 T03/T04 环境和私有配置，按 README 的启动流程执行：

```sh
make setup-t05
make demo-t05
make test-data CASE=test_ingestion
```

`setup-t05` 准备内部数据库迁移，`demo-t05` 运行手动合成演练，`test-data CASE=test_ingestion` 验证 T05 工程行为。健康命令发送到 NocoBase 本机 13000 端口的 `POST /api/opsDataHealth:ingest`；演练仅用 synthetic 来源与本地验收账号。该命令不意味着 18000 数据服务已提供生产采集入口，也不意味着已安装周期 worker。

最终集成验证（2026-10-26）：

- `make setup-t05` 通过：构建服务、三组幂等数据库迁移、刷新自有数据健康页；原页备份保存在本地 `.local/ui-backups`。
- `make test` 通过：工具50、Python契约28、数据库健康3、T04连接器47、T05采集56、插件HTTP/客户端28、Node契约4，共216项不同用例。契约在完整命令中额外复跑一次，不重复计数。无跳过；社区来源检查101个安装/77个启用，双库账号隔离通过。
- 两次连续 `make demo-t05`：同一batch返回4条源事实、2笔平台订单、销量6、1条待评估；健康投递从2条降为0，未重复发送。此处 complete 仅表示已知的合成数据集完整。
- 重启 ops-data 后，再按当前配置版本执行两次演练，结果相同。原版本批次/快照保留；新版本使用同一合成连接及新batch，旧stream与旧待投递命令不覆盖当前摘要。
- 独立审查发现并修复：失效租约提交、映射升级混用、双方缺值误对账一致、成功收执重放失败、健康接口覆盖受限读取导致的跨店泄漏。后者补列表/详情/过滤/展开/CRUD真实HTTP回归。

浏览器功能验收：Ego Lite用合成A店运营登录，数据健康页可见订单采集成功、退款需人工处理及对应待办；查看待办详情能看到数据类型、问题分类、负责人、店铺与测试来源，A店列表未显示B店种子记录。窗口处于最小化状态，截图工具拒绝截图，因此没有视觉布局验收截图。页面中文数据类型与恢复标签已补齐，构建及页面资源测试2项通过，HTTP静态包包含新标签；浏览器本轮仍读到旧缓存标签，未宣称新标签的视觉验收通过。

## 真实验收仍缺的证据

1. 两店与仓库真实身份、正式只读权限、产品版本、字段/状态/时区/分页映射及明确业务口径；mapping_confirmed 必须有人工证据，不是自动真实确认。
2. 两店默认 28 个完整业务日的真实历史回补、迟到回扫和完整性证明；查询修改时间范围不能充当业务日覆盖证明。
3. 20 个真实订单、10 个 SKU、退款样本及日汇总的逐项对账，拆合、取消、更正、退款来源和共仓差异须保留解释证据。
4. 真实端到端采集适配、调度 worker 安装及可恢复执行演练。当前真实投递保持关闭。
5. 原始页暂存的脱敏字段白名单、访问约束、保留与清理周期；当前暂存工程尚未完成这些生产数据治理措施。

同一 scope/data_type 必须使用单一权威连接，避免多个连接竞争同一健康摘要。数据服务只写自有 ops 数据库，人员和配置仍以 NocoBase 为权威。synthetic、manual_import 与 wdt_api 来源必须明确区分，不能把合成结果冒充真实验收。
