# T03 合成工作台复现与验收

本阶段范围为业务模型、四个工作台入口、人员业务范围、规则版本命令与审计。所有店铺、任务、异常、健康记录和规则验收均为 `synthetic`。真实两店的身份、授权、业务参数和T01资料尚未确认；本阶段不连接旺店通、Ego或生产店铺，不提供自动巡检、派单、证据上传和复查。

## 本机复现

确认专用Colima实例运行并具备 README 所列依赖后，在仓库根目录执行：

```sh
make bootstrap
make setup-dev
make setup-t03
make status
make test-plugin
```

`setup-t03`先构建自研客户端、启动服务、安装/核验插件。容器内的可信种子程序使用 `NODE_MODULES_PATH=/app/nocobase/node_modules`，没有HTTP种子接口。容器操作均经 `scripts/compose.sh`，沿用项目Docker context及本机部署配置。

凭据保存在 `.local/secrets/t03-accounts.json`，目录0700、文件0600。已有本机凭据会私密传回容器 `/tmp/t03-accounts.json` 后再执行种子程序；已有密码保持不变。容器已有完整记录而本机文件缺失时，可安全取回。账号已存在却没有凭据记录时停止，不生成替代密码。凭据内容、密码和底层进程输出不写入控制台。修改登录密码后需同步更新此私密文件，脚本不会重置账号密码。

种子程序在创建每个用户前先原子保存其凭据，因此首次失败时文件可能只有部分账号，最新账号也可能尚无用户ID。安装脚本会在失败后尝试取回这份恢复记录，验证其结构及已有邮箱/密码没有变化，再原子保存到本机0600文件，随后以非0退出并停止页面配置。下次会把该部分记录传回容器继续；只有全部四个账号及用户ID齐备才进入成功路径。如果取回失败或凭据不一致，保留原本机文件并报错；此时先保留容器并恢复记录，不要重建容器导致尚未取回的恢复记录丢失。

合成种子会恢复约定的A/B店、成员、仓库授权和任务演示基线，并修复事件业务UUID引用；因此重复执行适用于本地验收，不是保留任意手工改动的生产迁移。规则命令创建的版本和审计历史不会被此脚本清空。

页面配置仅管理 `ops_t03_tasks`、`ops_t03_incidents`、`ops_t03_health`、`ops_t03_settings`。默认不替换已有页面布局，其他页面及其角色菜单关系保留。必要的自有页面替换由 `node scripts/setup-nocobase-pages.mjs --replace-pages` 完成，并将旧结构以0600写入 `.local/ui-backups/`；这不是默认安装步骤。源码配置见 `config/nocobase-pages.mjs`，导出的结构在 `docs/nocobase-config/pages.json`。

## 账号与页面检查

管理员使用 `.local/secrets/deploy.env` 中的本机管理员凭据。其余账号通过本机账号文件的 `supervisor`、`operatorA`、`operatorB`、`integration` 项读取；不要复制凭据到验收截图、文档或聊天。

| 检查 | 预期行为 |
|---|---|
| 管理员登录 | 可进入四个自有页面，维护合成配置与负责人，发布/启停规则 |
| 主管登录 | 可见授权A/B店及授权共仓；可在范围内发布规则；人员及店铺配置只读 |
| A/B店运营登录 | 可见对应店铺异常/健康记录；任务必须同时符合业务范围和本人负责人；无管理入口 |
| 集成账号登录/API | 无自有业务页面菜单；只能读取授权范围；配置/规则命令拒绝 |
| 任务详情 | 只读详情和只读事件时间线；事件引用业务UUID，来源标记合成集成账号 |
| A店运营直接猜B店详情 | 返回404；不能因直接构造URL绕过范围 |
| 共仓任务 | 没有仓库授权的运营不可见，即使已被指定为负责人 |
| 直接CRUD、导出、query、关系展开 | 关键业务资源拒绝普通写入与旁路读取；通用导出当前明确403 |
| 已有token的成员授权或全局业务角色撤销 | 下一次请求立即失去对应范围；全局业务角色移除后业务API返回403；恢复后重新可见 |
| 过期配置版本/相同命令重试 | 过期版本409；同调用者、同命令ID及同参数返回原持久收执；改参数或改调用者409 |

菜单只是入口。服务端重新读取NocoBase角色、有效StoreMembership和WarehouseScope；请求体自报角色、actor或客户端显示状态不参与授权。任务子记录继承被引用任务的可见性。

## 可重复验证命令

```sh
# 私密文件处理、分发映射及基础工具；不更改业务数据库
make test-bootstrap
make verify-contracts

# 下列插件测试需要已运行的本机合成环境，会新增合成版本和事件
make test-plugin CASE=scope
make test-plugin CASE=rules
make test-plugin CASE=pages
make test-plugin

# 完整已实现范围，以及社区版和数据库隔离检查
make test
```

`make test-plugin`一次串行运行bootstrap、scope、rules、pages、client；scope/rules共享全局配置版本，不可另开两个并行测试进程。`tasks`、`evidence`、`reviews`、Ego及端到端工作流仍未实现，对应命令必须以非0退出。

OpenAPI将T03三个配置/规则接口指向 `http://127.0.0.1:13000`，使用NocoBase登录令牌及 `{data: ...}`响应包装。`expected_version`为快照中的整数，不是待实现采集协议的十进制字符串；命令体也不使用该采集协议的签名信封。数据服务 `http://127.0.0.1:18000`仍只提供健康检查，其他经营端点继续标记pending。
