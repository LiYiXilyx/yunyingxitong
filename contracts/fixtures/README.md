# 样本分类与来源要求

当前没有真实脱敏样本，也没有以真实来源命名的占位数据。此目录说明仅建立样本接收标准，不能作为T01真实授权或业务验收证据。

## 三类来源分别记录

| 类型 | 标记 | 用途与边界 |
|---|---|---|
| 人工合成 | synthetic | 后续单元/合约用例；不得标记真实、脱敏真实或授权取数成功 |
| 真实脱敏样本 | real_redacted | 经授权源数据脱敏，核对字段和拆合等业务语义；原件及包含真实信息的版本仅在 `.local/intake/` 存储，不入Git |
| 历史回放 / 人工文件导入 | replay / manual_import | 同时保留原始来源类型和采集方式；不是本轮真实接口调用，也不替代真实完整同步验收 |

仓库只接收经审核可公开的完全匿名化衍生夹具，必须明确标记来源类别。用户填写副本、真实原件、仅脱敏但仍可识别商户的资料不入Git；不在此目录创建正式资料占位文件。

## 接收清单

每份资料的受控索引记录：来源类别、采集方式、授权责任人确认、源产品/版本/端点、两店匿名代号、范围/窗口/源时区、原件受控引用、脱敏方法、关联键替换表的受控引用、预期核验结果、核验人和日期。索引入库前也需审查，不暴露真实商户与凭据。

按店分别覆盖：正常支付、拆单、合单、取消、部分退款、全额退款、共享仓SKU、组合装/BOM、退款申请主子单。应保留边界与零值、缺失值、状态更正、跨页重复/错店场景；不存在的真实场景记缺口，后续合成用例另列。

脱敏必须保留主子单、平台单、退款、店铺、仓库、SKU之间的一致关联与字段类型。删去姓名、地址、电话、邮箱、物流标识、账号、Cookie、密钥和业务备注中的个人信息；ID使用稳定替换，不能删掉关联键后宣称可验证拆合去重。日期移位若改变业务日、观察窗或迟到顺序，必须说明，不能据此进行真实效果验收。

正式SID、appName、appkey、签名、密码、会话与授权头不得出现在夹具、下载文件、截图、日志或Git历史中。空白模板见[两店资料](../../docs/intake/two-stores.md)，候选字段见[字段字典](../../docs/field-dictionary.md)。
